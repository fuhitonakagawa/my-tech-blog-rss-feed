はじめにGMOコネクトの永田です。同じ長い資料を渡して、出力する JSON の形だけを変えながら Claude を何回か呼ぶ、というようなアプリを開発していました。プロンプトの前半（資料の部分）はどの呼び出しでも同じなので、プロンプトキャッシュが効いて、費用も待ち時間も減るだろうと思っていました。ところが、構造化出力（JSON Schema で出力の形を指定する機能）で受け取っていると、スキーマを変えた呼び出しではキャッシュが効きませんでした😇調べると、スキーマはプロンプトの前のほうに足されていました。スキーマを本文（依頼文の末尾）に自分で書く形に変えると、4つのスキーマで1つのキャッシュを共有できました。この記事は、Amazon Bedrock（以下 Bedrock）の Converse API で、スキーマの2つの渡し方を比べ、トークン数・費用・速さを測った記録です。先にまとめClaude Sonnet 5.5 に、同じ資料（約2万トークン）とスキーマの違う依頼を4回送ったときの比較です。観点構造化出力スキーマを本文に書くキャッシュの共有同じスキーマ同士だけ。4種なら4回書き込み4
