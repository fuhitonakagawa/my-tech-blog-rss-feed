最近の発表
AWS Identity and Access Management (IAM) アウトバウンド ID フェデレーションは、OpenID Connect (OIDC) ディスカバリ API 向けの Amazon Virtual Private Cloud (VPC) エンドポイントをサポートするようになりました。トラフィックをパブリックインターネットに通過させることなく、AWS PrivateLink を使用して VPC 内から OIDC ディスカバリメタデータおよび JSON Web Key Set (JWKS) 検証キーエンドポイントにアクセスできるようになります。IAM アウトバウンド ID フェデレーションにより、AWS ワークロードが外部サービスにアクセスする際に、長期的な認証情報を使用する必要がなくなります。代わりに、ワークロードは AWS Security Token Service (AWS STS) に有効期限の短い JSON Web Token (JWT) をリクエストします。外部サービスは、OIDC ディスカバリエンドポイントで利用可能な公開検証キーとメタデータを使用してこれらのトークンを検証します。これまで、OIDC ディスカバリエンドポイントにはパブリックインターネット経由でしか到達できなかったため、インターネットアクセスをもたない VPC で実行されている検証ワークロードはそれらを取得できませんでした。今回のリリースにより、インターフェイス VPC エンドポイントを作成してこれらのエンドポイントにプライベートに到達するようにし、検証キー取得のトラフィックを AWS ネットワーク内にとどめておくことができます。この機能は、外部サービスによる JWT 検証を可能にしながら、インターネットアクセスが制限された VPC で動作するワークロードのネットワークセキュリティ要件を満たすのに役立ちます。この機能は、すべての商用 AWS リージョン、AWS GovCloud (米国) リージョン、中国リージョンでご利用いただけます。標準の AWS PrivateLink の料金以外に追加料金はかかりません。詳細については、IAM ユーザーガイドを参照してください。

本日、AWS Billing and Cost Management (BCM) では、BCM ダッシュボードでの Detected Anomalies ウィジェットのサポートを発表しました。これにより、コストの異常を、コストと使用状況、予算、コスト効率、Savings Plans とリザーブドインスタンスのカバレッジおよび使用率に関するレポートと併せて確認できます。用途に合わせた 1 つのダッシュボードで、支出、コミットメント、コストの異常をまとめて把握できます。Detected Anomalies ウィジェットには、検出された異常の件数と、月初来の支出に対するコスト影響の合計が表示されます。これにより、それぞれの異常の規模をすぐに把握できます。異常ごとにコストへの影響、根本原因、継続期間を確認できます。30 日、60 日、90 日のいずれかのルックバック期間を選択し、重要度、サービス、アカウント、リージョンでフィルタリングすることで、各ダッシュボードにそのアカウントと最も関連の深い異常を表示できます。BCM ダッシュボードに 1 つまたは複数の Detected Anomalies ウィジェットを追加することで、財務チームやクラウド管理者は、既存のコスト管理ワークフローの中で異常をモニタリングできます。このウィジェットは AWS コスト異常検出コンソールに直接リンクしているため、異常の調査と評価の記録を簡単に行えます。ダッシュボードのエクスポート機能に完全に統合されており、スケジュール設定されたメールレポートに含めたり、オフライン分析用に CSV または PDF でダウンロードしたりできます。また、クロスアカウントのダッシュボード共有にも対応しています。BCM ダッシュボードの Detected Anomalies ウィジェットは、すべての AWS 商用リージョンで追加料金なしで利用できます。詳細については、ユーザーガイドをご覧ください。

AWS Billing Conductor がカスタム料金と使用量ティアの料金設定をサポート
最近の発表
AWS Billing Conductor では、AWS のサービスのカスタム料金を定義できるようになりました。また、任意の使用量に応じて料金を設定するためのカスタム使用量ティアも定義できるようになりました。 AWS Billing Conductor を使用して子会社、関連会社、またはエンドカスタマーとの商用契約をモデル化しているお客様やパートナーは、交渉により決定した料金をプロフォーマ請求データにこれまでより簡単に反映できます。SKU を範囲とする料金設定ルールを使用すると、カスタム料金を入力し、使用量ティアのしきい値を設定できます。事前定義された AWS の使用量ティアに紐づくパブリックのオンデマンド料金に対して、割増や割引を設定する必要はありません。 料金設定ルールで正確な料金とティアの区切りを直接設定することで、商用契約をモデル化する際に、パブリックのオンデマンド料金に対する割増率や割引率を計算する必要がなくなります。これにより、プロフォーマ請求の設定を細かく制御できます。SKU を範囲とする料金設定ルールによるカスタム料金とカスタム使用量ティアの設定は、Sinnet が運営する Amazon Web Services 中国 (北京) リージョンと、NWCD が運営する Amazon Web Services 中国 (寧夏) リージョンを除く、すべての AWS 商用リージョンで利用できます。 詳細については、AWS Billing Conductor の製品ページやユーザーガイドを参照してください。

AWS Step Functions が AWS Lambda MicroVMs をはじめとする AWS のサービスの新しい統合を自動追加
最近の発表
AWS Step Functions では、AWS の新しいサービスや機能に対する AWS SDK 統合を、リリースから数週間以内に自動的に追加するようになりました。まずは AWS Lambda MicroVMs や AWS Lambda Core などが対象です。これにより、更新を待つことなく、AWS の最新のサービスをワークフローからオーケストレーションできます。 今回の拡張には、AWS パートナーセントラル Revenue Measurement、AWS Resilience Hub V2、AWS Support Authorization、Amazon SageMaker Job Runtime も含まれます。今後は、AWS の新しいサービスがリリースから数週間以内に Step Functions の統合として自動的に表示されます。追加の設定や操作は必要ありません。更新は継続的に行われるため、AWS SDK の新しいサービス統合に関する更新を個別に取り上げる「新着情報」記事は今後公開しません。 デベロッパーガイドを参照してください。サポート対象サービスの一覧について、AWS SDK サービス統合および統合リリース履歴で確認できます。
