最近の発表
AWS Key Management Service (KMS) で、モジュール格子ベースのキーカプセル化メカニズム (ML-KEM) がサポートされるようになりました。ML-KEM は NIST FIPS 203 で規定されたポスト量子暗号の標準規格であり、2 者間での共有シークレットの確立を可能にします。 NIST は、戦略的な暗号ロードマップ (NIST IR 8547 を参照) において、DH/ECDH キー合意や RSA ベースのキートランスポートといった従来のキー確立方式に代わるものとして ML-KEM を設計しました。 ML-KEM は、従来の方式が抱える「今収集して後で復号する (harvest now, decrypt later)」という脅威に対処します。これは、攻撃者が現時点でキー確立のやり取りを記録しておき、十分に強力な量子コンピュータが利用可能になった時点で共有シークレットを復元するという脅威です。 KMS は、NIST FIPS 203 で定義されている 3 つの ML-KEM キー仕様 (ML-KEM-512、ML-KEM-768、ML-KEM-1024) をすべてサポートしています。Encapsulate API は、パブリックキーを使用して、ランダムな 32 バイトの共有シークレットとその暗号文を生成します。Decapsulate API は、対応するプライベートキーを使用して、暗号文から共有シークレットを復元します。KMS は、ML-KEM キーペアのプライベートキーを、FIPS 140-3 レベル 3 の検証を受けたハードウェアセキュリティモジュール (HSM) で保護します。GetPublicKey API を使用してパブリックキーをエクスポートし、パートナー、クライアントアプリケーション、外部システムに配布できます。配布先では、AWS-LC、OpenSSL、Bouncy Castle などの暗号ライブラリを使用して、カプセル化オペレーションをローカルで実行できます。 ML-KEM は、中東 (UAE)、中東 (バーレーン)、中国の各リージョンを除き、KMS が利用可能なすべての AWS リージョンで利用できます。詳細については、AWS KMS デベロッパーガイドの「Key spec reference」を参照してください。

最近の発表
Amazon Bedrock Advanced Prompt Optimization は、プロンプトの短縮をサポートするようになりました。これは、評価スコアを維持または向上させながら、プロンプトの長さを短くするオプション設定です。Advanced Prompt Optimization は、独自の評価基準に対して、Amazon Bedrock 上の任意のモデルのプロンプトを最適化します。これまでは、最適化は品質のみに焦点を当てていました。そのため、最適化されたプロンプトは元のプロンプトよりも長くなることがよくありました。プロンプトが長くなると入力トークンのコストが上昇し、最初のトークンが出力されるまでの時間が増加する可能性があり、これは大規模な運用やレイテンシーの影響を受けやすいアプリケーションにおいて重要となります。 入力データセット内のプロンプトテンプレートに対してプロンプトの短縮をオンにすると、オプティマイザーはプロンプトの長さを短くします。最適化されたプロンプトは、それが元のプロンプトよりも短く、かつ評価スコアが同等以上である場合にのみ返されます。それ以外の場合は元のプロンプトが返されるため、この設定によって元のプロンプトより長くなったり、スコアが低くなったりすることはありません。結果には、圧縮率と、元のトークン数および最適化後のトークン数が、出力ファイルとコンソールの結果ページに含まれます。例えば、圧縮率が 0.7 の場合、最適化されたプロンプトが使用するトークン数が 30% 少ないことを意味します。プロンプトの短縮は、ステアリング基準、LLM-as-a-judge のルーブリック、カスタムの Lambda エバリュエーターなど、あらゆる評価方法で機能します。 プロンプトの短縮は、Advanced Prompt Optimization が利用可能なすべての AWS リージョンでご利用いただけます。使用を開始するには、入力データセット内のプロンプトテンプレートに対してプロンプトの短縮を有効にし、通常どおりに最適化ジョブを作成します。詳細については、Amazon Bedrock ユーザーガイドの Shorten prompts、Amazon Bedrock の料金ページ、および Amazon Bedrock の製品ページをご覧ください。
