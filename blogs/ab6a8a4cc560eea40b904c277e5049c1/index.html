Amazon SageMaker AI 推論で GPU パーティショニングがサポートされるようになりました。これにより、モデルごとにアクセラレーター全体を割り当てる代わりに、1 つの GPU で複数のモデルを実行できます。SageMaker AI は、NVIDIA Multi-Instance GPU (MIG) 技術を使用して、1 つの GPU を最大 7 つの独立したパーティションに分割します。各パーティションには、それぞれ専用のメモリとコンピューティングリソースが割り当てられます。これまで、ファインチューニングされた派生モデル、埋め込みモデル、リランカー、分類モデルなどの小規模から中規模のモデルを運用する場合、モデルごとにアクセラレーター全体を割り当てる必要がありました。そのため、インスタンスに配置できるモデルの数は GPU の数以下に制限され、モデルが使い切れない GPU の処理能力に対しても料金が発生していました。GPU パーティショニングでは、エンドポイントで使用する GPU の分割方法を指定し、各モデルの要件に合ったサイズのパーティションに配置できます。1 つのアクセラレーターで複数のモデルを実行しても、ハードウェアによってリソースが分離されるため、特定のモデルの負荷が高くなっても、同じ GPU 上の他のモデルに割り当てられたメモリやスループットを消費することはありません。アクセラレーターをワークロードの規模に合わせて調整できるため、従来は単一のモデルに対して容量が過剰だった新しい世代のインスタンスも、選択肢に加えられます。GPU パーティショニングは、推論コンポーネントをホストするエンドポイントの作成時に設定します。各モデルは引き続き名前で呼び出せるため、アプリケーションコードを変更する必要はありません。GPU パーティショニングは、米国東部 (バージニア北部)、米国東部 (オハイオ)、米国西部 (オレゴン)、アジアパシフィック (シンガポール)、アジアパシフィック (東京)、欧州 (フランクフルト)、欧州 (アイルランド) の P4d、P5、G7、G7e インスタンスで利用できます。詳細については、Amazon SageMaker AI のデプロイページにアクセスし、Amazon SageMaker AI デベロッパーガイドを参照してください。

AWS Backup が Amazon Redshift の復元テストをサポート
最近の発表
AWS Backup の復元テストで Amazon Redshift がサポートされるようになりました。復元テストを使用すると、バックアップの復元テストを自動化して定期的に実行できるため、Amazon Redshift のバックアップが正常に復元されることを確認し、復元にかかる時間を測定できます。 ストレージ、コンピューティング、データベースの各サービスにわたる、サポート対象の他の AWS リソースとともに、Amazon Redshift を復元テスト計画に含めることができるようになりました。復元テスト計画では、復旧ポイントが自動的に選択され、スケジュールに従って復元が実行され、目標復旧時間 (RTO) に照らして復元ジョブの完了までの所要時間が測定されます。これにより、リカバリの準備状況を評価し、ディザスタリカバリと事業継続に関する規制やコンプライアンスの要件を満たすことができます。 使用を開始するには、復元テスト計画を作成し、Amazon リソースネーム (ARN) またはタグを使用して Amazon Redshift リソースを割り当てます。各テストで、最新の復旧ポイントを復元するか、対象となる復旧ポイントからランダムに選んで復元するかを選択します。オプションで、復元テストの検証を使用して、AWS Backup がテストリソースを削除する前に、復元されたリソースを確認できます。 このサポートは、AWS Backup で復元テストと Amazon Redshift の両方がサポートされているすべての AWS リージョンで利用できます。AWS Backup コンソール、AWS コマンドラインインターフェイス (CLI)、または AWS SDK を使用できます。サポートされているリージョンと機能の完全なリストについては、AWS Backup のドキュメントを参照してください。復元テストの詳細については、製品ページおよび料金ページを参照してください。

AWS Marketplace と Amazon Business の統合ストアフロントを発表
最近の発表
