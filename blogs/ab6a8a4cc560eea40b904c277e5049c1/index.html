本日、Amazon Elastic Container Service (Amazon ECS) では、新しい ECS サービスメトリクスである LiveTaskCount が発表されました。このメトリクスは、サービス内でアクティブに実行されているタスクの数をレポートするもので、すべてのお客様が追加料金なしで利用できます。また、Amazon CloudWatch Container Insights の既存メトリクスである RunningTaskCount を、無料で利用できるようになりました。LiveTaskCount は、すべての目的のステータス (ACTIVATING、RUNNING、DEACTIVATING) にわたって、アクティブに実行されている ECS タスクの数をレポートします。これには、スケールインイベント中に Connection Draining が行われているタスクのように、停止状態への移行中でまだ実行中のタスクも含まれます。LiveTaskCount はこのようにすべての状態を網羅しているため、自動スケーリングポリシーやキャパシティプランニングに適しています。これらの用途では、メトリクスを生成しているアクティブなタスクの全体を把握する必要があります。LiveTaskCount は ECS サービス使用率メトリクスの一部として無料で利用でき、CloudWatch Container Insights へのオプトインは必要ありません。CloudWatch Container Insights の既存の RunningTaskCount メトリクスは、現在のステータスと目的のステータスの両方が RUNNING であるタスクを追跡します。このメトリクスは、これを利用しているお客様にとって、引き続き正常性と安定性を示す指標として機能します。本日の更新により、すべての CloudWatch Container Insights ユーザーが RunningTaskCount を追加料金なしで利用できるようになりました。これらの更新は、Amazon ECS が利用可能なすべての AWS リージョンで利用できます。お客様による対応は必要ありません。RunningTaskCount の料金変更は 2026 年 10 月 1 日から有効になり、自動的に適用されます

AWS IAM アイデンティティセンターは、従業員が AWS アカウントやアプリケーションにシングルサインオンできるように設定するのに役立ちます。IAM アイデンティティセンターでは、ユーザーとグループを保存するアイデンティティストアのネットワークアクセスコントロールがサポートされるようになりました。リクエストの発信元のネットワークに基づいて、アイデンティティストア API と SCIM API へのアクセスを制限できます。カスタムアプリケーションとユーザープロビジョニングワークフローではアイデンティティストア API を使用してユーザーとグループの管理と検索を行い、外部 ID プロバイダーでは SCIM API を使用してユーザーとグループを同期します。アイデンティティストア API では、アカウントまたは組織内の許可された VPC エンドポイント、または特定のソース VPC からのみリクエストが届くように設定できます。いずれの API でも、特定の IP 範囲からのリクエストのみを許可できます。同じ構成内で、各 API に異なる制限を適用できます。たとえば、アイデンティティストア API リクエストは VPC エンドポイントを経由した場合のみ届くようにしながら、外部 ID プロバイダーの公開された IP 範囲からの SCIM リクエストを許可できます。ネットワークアクセスコントロールはオプションであり、デフォルトではオフになっています。AWS サービスがお客様に代わって行うリクエストは対象外です。ネットワークアクセスコントロールは、AWS SDK と AWS CLI を通じてアイデンティティストア API を使用して設定します。この機能は、IAM アイデンティティセンターが提供されているすべての AWS リージョンでご利用いただけます。IAM アイデンティティセンターの詳細については、製品の詳細ページをご覧ください。ネットワークアクセスコントロールの使用を開始するには、アイデンティティストア API リファレンスを参照してください。

AWS Private CA で詳細な証明書発行ログの提供を開始
最近の発表
AWS Private CA では、詳細な証明書発行ログを発表しました。これは、証明書の全内容、発行元 CA 情報、リクエスタ ID、すべての発行の署名ステータスを記録する新しい AWS CloudTrail サービスイベントです。これらのイベントは、コンプライアンス監査、証明書インベントリ、アルゴリズム移行の追跡、発行失敗のモニタリングに使用できます。以前は、IssueCertificate API の CloudTrail 管理イベントでは、証明書の ARN を指定して API コールが成功したことが確認されましたが、証明書の内容、署名した CA に関する情報、署名前に失敗した発行はキャプチャされませんでした。新しい IssueCertificateDetails イベントでは、すべての X.509 フィールドと拡張子に加えて、サブジェクト、発行者、シリアル番号、有効期間、テンプレート、署名アルゴリズム用の便利なフィールドを含む、署名前 (TBS) 証明書全体がキャプチャされます。イベントは発行の成功と失敗の両方に対して発行されるため、名前の制約違反などの署名前の失敗で、失敗の説明を含むレコードが生成されるようになりました。各イベントではリクエスタが識別されます。リクエスタは、直接の API の呼び出し元の場合はアカウントと IAM プリンシパルであり、AWS Private CA コネクタまたは統合された AWS サービスを通じて発行された証明書の場合はサービスプリンシパルです。クロスアカウント構成では、イベントは CA 所有者アカウントに配信されます。イベントは CloudTrail 管理イベントとして自動的に配信され、設定やオプトインは不要で、標準の AWS CloudTrail 料金を超える追加費用もありません。CloudTrail を経由するため、Amazon EventBridge を使用してリアルタイムで処理することも、Amazon Athena を使用してバッチクエリを実行して、証明書の監査、インベントリ、追跡、モニタリングを行うこともできます。 この機能は、AWS Private CA が提供されているすべての AWS リージョンで利用できます。詳細については、AWS Private CA ユーザーガイドを参照してください。

本日、AWS は Agent Toolkit for AWS 向けの AWS コマンドラインインターフェイス (CLI) コマンドを拡張し、エージェントスキルを最新の状態に保ちやすくする 2 つの新機能を追加しました。aws agent-toolkit check-skill-updates を実行すると、インストールされているすべてのスキルと、レジストリで利用可能な最新バージョンを比較できます。また、aws agent-toolkit update-skill --all を使用すると、古くなったすべてのスキルを 1 つのコマンドで更新できます。Agent Toolkit for AWS は、AWS MCP サーバー、エージェントスキル、プラグインで構成されています。AWS MCP サーバーでは、15,000 を超える AWS API に安全かつ監査可能な方法でアクセスするためのエージェントインターフェイスを利用できます。エージェントスキルでは、ストレージ、ネットワーキング、分析など、さまざまな分野の専門的なガイダンスをエージェントに提供できます。プラグインでは、MCP サーバーと厳選されたスキルセットがまとめられており、1 回でインストールできます。これまでは、各スキルを個別にチェックして更新する必要がありました。今回 AWS CLI に追加された機能を利用すると、デベロッパーは新しいバージョンが利用可能なスキルをすばやく特定し、1 つずつ更新を管理することなく、スキルセット全体を最新の状態にできます。これは特に、サーバーレス、ストレージ、ネットワーキング、分析などの分野にわたって多数のスキルをインストールしており、コーディングエージェントで常に最新のガイダンスを使用したいチームに役立ちます。これらの新しいコマンドは、Agent Toolkit 向けの既存の AWS CLI 機能に追加されます。既存の機能では、Kiro、Claude Code、Codex、Cursor、その他の一般的なコーディングエージェントで、AWS MCP サーバーとエージェントスキルをインストール、検索、設定できます。 使用を開始するには、Agent Toolkit for AWS ユーザーガイドの AWS CLI を参照してください。AWS CLI バージョン 2.37.0 以降がインス

Amazon S3 Vectors、メタデータの事前フィルタリングによってフィルター検索の再現率が最大 5 倍に向上
最近の発表
Amazon S3 Vectors で事前フィルタリングがサポートされるようになりました。事前フィルタリングでは、類似性検索の実行前にメタデータフィルターが評価され、フィルターの選択性が高い場合、一致するベクトルが最大 5 倍多く返されます。また、S3 Vectors には、パスや URL などの値をフィルタリングするためのプレフィックス一致演算子 ($startsWith) も追加されました。これらの機能強化により、取得拡張生成 (RAG)、エージェンティック、セマンティック検索の各アプリケーションでフィルタリングを行う際に、より完全な結果を取得できるため、より関連性の高い回答を返せるようになります。S3 Vectors では、Amazon S3 にベクトルを保存してクエリするためのネイティブサポートとして、数十億規模のベクトルに対応するよう専用設計され、コスト最適化された保存機能とクエリ機能を利用できます。今回のリリースにより、新しいベクトルバケット内のインデックスでは、デフォルトでメタデータの事前フィルタリングが使用されます。PutVectors でベクトルを書き込む方法や、QueryVectors でフィルター付きクエリを実行する方法に変更はありません。既存のインデックスで事前フィルタリングを使用する場合は、UpdateIndexMode API を使用してインデックスをその場で更新できます。更新する前に QueryVectors のクエリごとのパラメータを使用して、同じインデックスで事前フィルタリングと現在のフィルタリングを比較することもできます。メタデータの事前フィルタリングは、Amazon S3 Vectors が提供されているすべての商用 AWS リージョンと AWS 中国リージョンで、追加料金なしで利用できます。現在、この変更のデプロイを進めており、近日中にデプロイを完了する予定です。使用を開始するには、AWS CLI、AWS SDK、または Amazon S3 コンソールを使用してください。詳細については、Amazon S3 Vectors のドキュメントおよび AWS ニュースブログを参照してください。

AWS Parallel Computing Service、スケーリングログのサポートを開始
最近の発表
AWS Parallel Computing Service (AWS PCS) では、クラスター内のコンピューティングノードグループのスケーリング状況を記録するスケーリングログがサポートされるようになりました。各ログエントリには、1 つのコンピューティングノードで発生した 1 回の状態遷移が記録されます。例えば、インスタンスの起動、ノードの登録、スケールダウン、起動の失敗とその理由などです。スケーリングログを使用すると、スケーリング問題のトラブルシューティングが簡単になります。例えば、コンピューティングノードグループがターゲットサイズに達しなかった理由、キャパシティ上の理由で失敗した起動、あるノードが開始または停止した時刻を特定できます。AWS PCS でのスケーリングログの配信はオプトイン方式です。スケーリングログの出力先には、Amazon CloudWatch Logs、Amazon S3、Amazon Data Firehose を指定できます。AWS PCS は、Slurm を使用して AWS での HPC ワークロードの実行とスケーリングを簡素化するマネージドサービスです。コンピューティング、ストレージ、ネットワーク、可視化ツールを統合した包括的で伸縮自在な環境を構築できます。クラスターの運用は、マネージド更新や組み込みのオブザーバビリティ機能により、サービス側で処理されます。この機能は、AWS PCS が提供されているすべての AWS リージョンでご利用いただけます。使用を開始するには、AWS PCS ユーザーガイドを参照してください。
