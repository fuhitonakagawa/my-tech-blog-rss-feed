AWS Private CA では、詳細な証明書発行ログを発表しました。これは、証明書の全内容、発行元 CA 情報、リクエスタ ID、すべての発行の署名ステータスを記録する新しい AWS CloudTrail サービスイベントです。これらのイベントは、コンプライアンス監査、証明書インベントリ、アルゴリズム移行の追跡、発行失敗のモニタリングに使用できます。以前は、IssueCertificate API の CloudTrail 管理イベントでは、証明書の ARN を指定して API コールが成功したことが確認されましたが、証明書の内容、署名した CA に関する情報、署名前に失敗した発行はキャプチャされませんでした。新しい IssueCertificateDetails イベントでは、すべての X.509 フィールドと拡張子に加えて、サブジェクト、発行者、シリアル番号、有効期間、テンプレート、署名アルゴリズム用の便利なフィールドを含む、署名前 (TBS) 証明書全体がキャプチャされます。イベントは発行の成功と失敗の両方に対して発行されるため、名前の制約違反などの署名前の失敗で、失敗の説明を含むレコードが生成されるようになりました。各イベントではリクエスタが識別されます。リクエスタは、直接の API の呼び出し元の場合はアカウントと IAM プリンシパルであり、AWS Private CA コネクタまたは統合された AWS サービスを通じて発行された証明書の場合はサービスプリンシパルです。クロスアカウント構成では、イベントは CA 所有者アカウントに配信されます。イベントは CloudTrail 管理イベントとして自動的に配信され、設定やオプトインは不要で、標準の AWS CloudTrail 料金を超える追加費用もありません。CloudTrail を経由するため、Amazon EventBridge を使用してリアルタイムで処理することも、Amazon Athena を使用してバッチクエリを実行して、証明書の監査、インベントリ、追跡、モニタリングを行うこともできます。 この機能は、AWS Private CA が提供されているすべての AWS リージョンで利用できます。詳細については、AWS Private CA ユーザーガイドを参照してください。

Amazon RDS で RDS スナップショットのフルスナップショットサイズが表示されるようになりました。この機能強化により、DescribeDBSnapshots API の新しいフィールド FullSnapshotSizeInBytes を利用して、プログラムからフルスナップショットサイズを取得できます。この情報は、コンソールの [フルスナップショットサイズ] 列で確認することもできます。 Amazon RDS スナップショットはインクリメンタルです。このため、あるボリュームのスナップショットを時間の経過とともに複数作成すると、各スナップショットには新しいブロックまたは変更されたブロックのみが保存され、過去のスナップショットから変更されていないブロックへの参照が維持されます。[FullSnapshotSizeInBytes] フィールドには、そのスナップショットで直接保存されたブロックと、過去のスナップショットから参照されるすべてのブロックの両方を含めた、スナップショットの合計ブロックサイズが表示されます。例えば、100 GB のデータベースボリュームに 50 GB のデータがある場合、フルスナップショットサイズは、最初のスナップショットか後続のスナップショットかにかかわらず 50 GB と表示されます。これは増分スナップショットサイズとは異なることに注意してください。増分スナップショットサイズは、新たに変更されて、特定のスナップショットに保存されたブロックのサイズのみを示します。フルスナップショットサイズは、すべての商用 AWS リージョンにおいてすべての Amazon RDS データベースインスタンスで確認できます。Amazon RDS マネジメントコンソール、AWS コマンドラインインターフェイス (CLI)、または AWS SDK を使用して、今すぐ使用を開始できます。詳細については、Amazon RDS ユーザーガイドをご覧ください。

AWS Backup が Amazon FSx for NetApp ONTAP 向けの論理エアギャップボールトをサポートするようになりました。論理エアギャップボールトは、複数のアカウントや AWS Organizations でバックアップを安全に共有できるタイプの AWS Backup ボールトです。直接復元をサポートしており、データ損失イベントからの復旧時間を短縮します。Amazon FSx for NetApp ONTAP ボリュームを論理エアギャップボールトで保護できるようになりました。論理エアギャップボールトに保存される変更不可能なバックアップは、デフォルトでロックされており、AWS が所有するキーまたはカスタマーマネージドキーを使用して暗号化され分離されています。同じアカウント内または他のアカウントやリージョンにわたって、論理エアギャップボールトに FSx for NetApp ONTAP バックアップを保存できます。これにより、ダウンタイムのリスクを軽減し、ビジネス継続性を確保し、コンプライアンスとディザスタリカバリの要件を満たすことができます。利用を開始するには、AWS Backup コンソール、AWS コマンドラインインターフェイス (CLI)、AWS SDK を使用できます。バックアップ計画でプライマリターゲットまたはコピー先として指定することで、論理エアギャップボールトを FSx for NetApp ONTAP バックアップのターゲットに設定します。AWS Resource Access Manager (RAM) を使用して他のアカウントとボールトを共有し、リカバリや復元テストを行ったり、アカウントが乗っ取られた際にもマルチパーティー承認を使用してボールトへのアクセスを保護したりできます。利用可能になると、そのアカウントから直接復元ジョブを開始できるため、最初にバックアップをコピーする手間が省けます。このサポートは、論理エアギャップボールトと Amazon FSx for NetApp ONTAP の両方が利用可能なすべての AWS リージョンでご利用いただけます。詳細および利用可能なリージョンについては、AWS Backup のドキュメントをご覧ください。論理エアギャップボールトの詳細については、機能に関するドキュメントと料金表のページ

Amazon Transcribe がカスタムリソース向けにカスタマーマネージド KMS キーのサポートを追加
最近の発表
Amazon Transcribe では、お客様が所有および管理するカスタマーマネージド AWS KMS キーを使用して、カスタム語彙、カスタム語彙フィルター、およびカスタム言語モデルを保管時に暗号化できるようになりました。これまでは、これらのカスタムリソースは常に AWS が所有するキーで暗号化されていました。これらのリソースを作成または更新する際に独自の対称 AWS KMS キーを指定できるようになったため、Transcribe がお客様に代わって保管するアーティファクトは、お客様のアカウント内にあるキーの下で暗号化されます。キーを指定しない場合、リソースは引き続いて AWS が所有するキーで暗号化されるため、オプトインしない限りアクションは不要です。カスタマーマネージドキーを使用すると、キーのアクセス許可を制御し、どのプリンシパルやサービスがカスタムリソースを暗号化および復号できるかを正確に決定できます。キーの使用履歴はすべて AWS CloudTrail に記録されるため、コンプライアンスやモニタリングのための完全な監査証跡が得られます。また、アクセス許可を取り消すために、独自のスケジュールでキーを無効化したり、リソースを別のキーに移行したりすることも可能です。この機能は、Amazon Transcribe が提供されているすべての AWS リージョンでご利用いただけます。詳細については、Amazon Transcribe デベロッパーガイドを参照してください。
