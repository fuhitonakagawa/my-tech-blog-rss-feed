本日、AWS は、Amazon Bedrock AgentCore のサーバーレス microVM コンピューティングである AgentCore Runtime の次世代版の提供開始を発表しました。新しい Runtime は、セッション全体を通じて未使用のメモリを回収する伸縮性のあるメモリ管理を実現します。これにより、ピーク時の使用量ではなく、実際の使用量に対して料金を支払うことになります。また、コンテナイメージのサイズや同時実行数に関係なく、一定のコールドスタート時間を実現します。これまでのサーバーレスモデルのメリットは、そのまま維持されます。事前プロビジョニングは不要で、ゼロまでスケールダウンでき、セッションはハードウェアレベルで分離され、料金は使用した分のみ発生します。そのうえで、コストが削減され、起動が高速になりました。新しい Runtime では、各セッションは小規模で効率的なメモリプロファイルで開始されます。追加のメモリはワークロードの必要に応じてオンデマンドで割り当てられ、アクティブに使用されなくなったメモリは、セッション終了まで保持されずに回収されます。コールドスタートについては、新しい Runtime がエージェント環境を一度準備し、そのスナップショットを作成します。新しいインスタンスはすべて、起動シーケンス全体を繰り返す代わりにこのスナップショットから復元されます。そのため、イメージサイズに関係なく起動時間が一定に保たれます。テストでは、200 MB～2 GB のコンテナイメージにおいて、新しい Runtime の P75 コールドスタート時間は 1.9～2.0 秒でした。これに対し、V1 では 5.4～30 秒でした。新しい AgentCore Runtime は、us-east-1、us-east-2、us-west-2、eu-west-1、ap-northeast-1 の各リージョンで利用できます。 使用を開始するには、ランタイムの作成時または更新時に platformVersion を V2 に設定してください。詳細については、AgentCore Runtime のドキュメントや AWS ニュースブログを参照してください。料金の詳細については、AgentCore の料金を参照してください。

Amazon EBS Volume Clones がアカウント間でのボリュームコピーに対応
最近の発表
Amazon Elastic Block Store (Amazon EBS) Volume Clones が、再暗号化を伴う AWS アカウント間の EBS ボリュームのコピーに対応しました。EBS ボリュームを任意の AWS アカウントにコピーし、ターゲットアカウントの AWS Key Management Service (AWS KMS) キーを使用して再暗号化できます。これにより、本番環境と開発環境のワークロードを別々のアカウントに分離している組織でも、アカウントの境界を越えてデータをコピーすることが可能になります。クロスアカウントコピーを使用すると、本番データベースのボリュームを独立した開発用アカウントへクローンできるため、開発者は安全に実験を行える最新の本番データコピーを手に入れることができます。この機能は、本番アカウント用と非本番アカウント用で個別の KMS 鍵を維持するなど、環境ごとに暗号化キーの分離を必要とするチームにとっても役立ちます。クロスアカウントコピーは、暗号化されていないボリュームやカスタマーマネージドキーで暗号化されたボリュームを含む、すべてのボリュームタイプでサポートされています。アカウント間でボリュームをコピーするには、まず AWS Resource Access Manager (AWS RAM) を使用してコピー先のアカウントにボリュームを共有し、次にコピー先のアカウントで、同じアベイラビリティゾーン内に共有ボリュームのコピーを作成します。この機能には、AWS マネジメントコンソール、AWS コマンドラインインターフェイス (CLI)、AWS SDK を使用してアクセスできます。Amazon EBS Volume Clones をサポートするすべての AWS リージョンでご利用いただけます。これには、すべての商用リージョン、AWS GovCloud (米国) リージョン、AWS 中国リージョン、およびサポートされているローカルゾーンが含まれます。詳細については、Amazon EBS Volume Clones のドキュメントをご覧ください。
