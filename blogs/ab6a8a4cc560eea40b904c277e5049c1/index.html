AWS GovCloud (米国東部、米国西部) リージョンにおいて、Amazon MSK Replicator を使用して、Amazon MSK クラスター間、さらにはオンプレミス、AWS 上のセルフマネージド型、または他のクラウドプロバイダーを含む外部の Apache Kafka クラスターから Amazon MSK プロビジョンドクラスターへ、ストリーミングデータをレプリケートできるようになりました。 MSK Replicator は Amazon MSK の機能の 1 つで、Kafka クラスター間のデータレプリケーションを自動化します。これにより、カスタムレプリケーションインフラストラクチャを管理したり、オープンソースツールを設定したりする必要がなくなります。MSK Replicator を使用すると、リージョンでの耐障害性に優れたストリーミングアプリケーションを簡単に構築し、可用性とビジネス継続性を向上させることができます。MSK Replicator では Kafka クラスター間の自動非同期レプリケーションを実現できるため、カスタムコードの記述、インフラストラクチャの管理、クロスリージョンのネットワーク設定が不要になります。MSK Replicator は基盤となるリソースを自動的にスケールするため、容量をモニタリングまたは拡張しなくてもオンデマンドでデータをレプリケートできます。MSK Replicator では、トピック構成、アクセスコントロールリスト (ACL)、コンシューマーグループのオフセットなど、必要な Kafka メタデータもレプリケートされます。あるリージョンで予期しないイベントが発生した場合は、他の AWS リージョンにフェイルオーバーして、シームレスに処理を再開できます。 Amazon MSK コンソールまたは Amazon CLI から MSK Replicator の利用を開始できます。詳細については、MSK Replicator のドキュメント、製品ページ、料金ページを参照してください。

Amazon Redshift が SUPER データ型を拡張し、最大 1,600 万バイトの文字列を保存可能に
最近の発表
Amazon Redshift が、SUPER データ型において最大 1,600 万バイトの個別の文字列をサポートするようになりました。データベースパラメータを通じてオプトインすると、JSON、PARQUET、TEXT、および CSV のソースファイルから構造化データや半構造化データを取り込む際や、抽出、ロード、変換 (ELT) プロセスを通じてデータを変換する際に、この機能強化が適用されます。これまでは、SUPER データ型内の個別の文字列は 65,535 バイトに制限されていました。 SUPER データ型に巨大な個別の文字列を保存することで、ソースデータを Amazon Redshift に保存するために必要だった読み込み前の複雑な変換を回避できます。これにより、65,535 バイトを超える大きな個別の文字列 (利用規約や契約書などの長いドキュメントなど) を追加の処理なしで直接取り込み、SQL を使用してクエリを実行できるようになります。データが Amazon Redshift に取り込まれた後は、PartiQL 言語の柔軟性を利用してデータを探索およびナビゲートしたり、文字列関数を使用してデータを変換したりできます。 JSON_PARSE、CONCAT、LISTAGG などの関数は、最大 1,600 万バイトの長さの入力文字列を受け取り、出力文字列を返すことができるようになりました。 この機能強化は、Amazon Redshift が利用可能な、AWS GovCloud (米国) リージョンを含むすべての AWS リージョンでご利用いただけます。詳細については、AWS リージョン表をご覧ください。さらに詳しく知るには、ドキュメントまたはブログをご覧ください。

AWS が EC2 Capacity Blocks for ML の償却サポートを開始
最近の発表
AWS Data Exports for Cost and Usage Report (CUR) 2.0 および AWS Cost Explorer は、Amazon EC2 Capacity Blocks for ML の前払い料金を、各予約の期間全体にわたって償却するようになりました。キャパシティブロックに起動された各インスタンスの償却コストと、未使用のキャパシティの償却コストを確認できるため、前払い料金を実際にそれを利用したワークロードに割り当てたり、使われなかったキャパシティを特定したりできます。 これまでは、キャパシティブロックの前払い料金は購入日に 1 回の請求として表示されていたため、そのコストが予約期間中の使用状況全体にどのように分散されているかを把握することが困難でした。今後は、償却コストがインスタンスの使用状況とともに表示されるため、リザーブドキャパシティで実行されたチーム、プロジェクト、およびアプリケーションに GPU コストを正確に割り当てることができるようになります。また、予約のうちどの程度の割合が未使用になったかを確認し、将来のキャパシティブロックの購入計画に役立てることもできます。CUR 2.0 では、償却コストは reservation_amortized_upfront_fee_for_billing_period と reservation_effective_cost の各列に表示され、reservation_net_effective_cost には割引適用後の償却コストが表示されます。Cost Explorer では、償却コストビューを選択することで、予約に対して割り当てられたキャパシティブロックのコストを確認できます。 キャパシティブロックの償却は、AWS GovCloud (米国) リージョンと中国リージョンを除く、すべての AWS リージョンで追加料金なしでご利用いただけます。詳細については、CUR 2.0 データディクショナリおよび Cost Explorer を使用したデータの探索に関するドキュメントをご覧ください。
