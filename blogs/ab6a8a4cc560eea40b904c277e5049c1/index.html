Amazon RDS for SQL Server と Amazon RDS for Oracle は、追加のストレージボリュームでの RDS ストレージの自動スケーリングをサポートするようになりました。RDS ストレージの自動スケーリングでは、増加するデータベースのワークロードに応じてストレージ容量がダウンタイムなしで自動的にスケールされます。 ストレージボリュームの追加では、ボリュームを最大 3 つ追加し、ストレージ容量を最大 256 TiB まで増やすことができます。以前は、プライマリストレージボリュームでは自動スケーリングを有効にできましたが、追加のストレージボリュームに対するストレージ容量のプロビジョニングは、予想されるアプリケーション容量の需要に基づいて手動で行う必要がありました。アンダープロビジョニングではアプリケーションのダウンタイムが発生する可能性があり、オーバープロビジョニングではリソースの使用率低下とコスト上昇が発生する可能性があります。RDS ストレージの自動スケーリングを使用すると、ユーザーは追加したストレージボリュームのそれぞれに対して希望する最大ストレージ制限を設定するだけで済み、あとは自動スケーリングによって処理されます。 RDS ストレージの自動スケーリングでは、実際のストレージ消費量が継続的にモニタリングされ、その消費量がプロビジョニングされているストレージ容量に近づくと、自動で容量のスケールアップが行われます。自動スケーリングは、新規のデータベースインスタンスと既存のデータベースインスタンスの両方で動作します。自動スケーリングには追加料金はかからず、プロビジョニングされたストレージリソースに対してのみお支払いいただきます。AWS マネジメントコンソール、AWS CLI、または Amazon RDS API を使用して有効にすることができます。 追加のストレージボリュームに対する RDS ストレージの自動スケーリングは、すべての商用 AWS リージョンと AWS GovCloud (米国) リージョンの Amazon RDS for SQL Server と Amazon RDS for Oracle で利用できます。詳細については、Amazon RDS ストレージの自動スケーリングに関するドキュメントをご覧ください。

Amazon Relational Database Service (Amazon RDS) for Oracle で、Oracle Database バージョン 19c および 26ai 向けの 2026 年 9 月の月次推奨パッチ (MRP) がサポートされるようになりました。MRP は、Oracle の Critical Security Patch Update (CSPU) と、Oracle が推奨する追加の修正がバンドルされた、四半期ごとのリリース更新 (RU) をベースとするマイナーエンジンバージョンです。2026 年 9 月の MRP は、2026 年 7 月の RU をベースに適用され、Oracle の 9 月の CSPU が含まれています。Oracle Database の最新のセキュリティ更新が含まれているため、2026 年 9 月の MRP にアップグレードすることをお勧めします。 このリリースには、更新された Oracle タイムゾーンファイル (DST バージョン 46) も含まれています。このファイルには、恒久的な UTC オフセットに移行する、カナダのブリティッシュコロンビア州とアルバータ州 (2026 年 11 月 1 日施行)、モロッコと西サハラ (2026 年 9 月 20 日施行) など、複数の地域における最新の夏時間ルールの変更が反映されています。これらの地域のタイムゾーン情報を含むタイムスタンプを保存している場合、更新されたタイムゾーンファイルにより、新しいルールに沿った状態にデータが保たれます。 新しいデータベースインスタンスに 2026 年 9 月の MRP を適用するか、Amazon RDS マネジメントコンソールから、あるいは AWS SDK または CLI を使用して、既存のインスタンスをエンジンバージョン 19.0.0.0.ru-2026-07.mrp-2026-09.r2 または 26.0.0.0.ru-2026-07.mrp-2026-09.r2 にアップグレードできます。Amazon RDS でサポートされている各エンジンバージョンの Oracle MRP の詳細については、Amazon RDS for Oracle リリースノートを参照してください。

Amazon Bedrock Advanced Prompt Optimization がプロンプトの短縮をサポート
最近の発表
Amazon Bedrock Advanced Prompt Optimization は、プロンプトの短縮をサポートするようになりました。これは、評価スコアを維持または向上させながら、プロンプトの長さを短くするオプション設定です。Advanced Prompt Optimization は、独自の評価基準に対して、Amazon Bedrock 上の任意のモデルのプロンプトを最適化します。これまでは、最適化は品質のみに焦点を当てていました。そのため、最適化されたプロンプトは元のプロンプトよりも長くなることがよくありました。プロンプトが長くなると入力トークンのコストが上昇し、最初のトークンが出力されるまでの時間が増加する可能性があり、これは大規模な運用やレイテンシーの影響を受けやすいアプリケーションにおいて重要となります。 入力データセット内のプロンプトテンプレートに対してプロンプトの短縮をオンにすると、オプティマイザーはプロンプトの長さを短くします。最適化されたプロンプトは、それが元のプロンプトよりも短く、かつ評価スコアが同等以上である場合にのみ返されます。それ以外の場合は元のプロンプトが返されるため、この設定によって元のプロンプトより長くなったり、スコアが低くなったりすることはありません。結果には、圧縮率と、元のトークン数および最適化後のトークン数が、出力ファイルとコンソールの結果ページに含まれます。例えば、圧縮率が 0.7 の場合、最適化されたプロンプトが使用するトークン数が 30% 少ないことを意味します。プロンプトの短縮は、ステアリング基準、LLM-as-a-judge のルーブリック、カスタムの Lambda エバリュエーターなど、あらゆる評価方法で機能します。 プロンプトの短縮は、Advanced Prompt Optimization が利用可能なすべての AWS リージョンでご利用いただけます。使用を開始するには、入力データセット内のプロンプトテンプレートに対してプロンプトの短縮を有効にし、通常どおりに最適化ジョブを作成します。詳細については、Amazon Bedrock ユーザーガイドの Shorten prompts、Amazon Bedrock の料金ページ、および Amazon Bedrock の製品ページをご覧ください。
