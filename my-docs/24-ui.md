qiita dedupで1000件以上投稿されてるっぽいんだけど、何が起きたの？

----

**Qiitaの大量投稿は、未掲載だった過去8日分の1,099記事をまとめて取り込んだためです。** 元チャンネルで配信済みでも、dedupでは初掲載として通知されます。既存370記事のGUID・初回掲載日時は維持されており、同じ1,099記事が毎回新着になる仕様ではありません。初回の大量通知について、説明が不足していました。

監視結果も確認できました。

- **[公開ページ](https://fuhitonakagawa.github.io/my-tech-blog-rss-feed/rss/qiita-dedup/)**：縦スクロールのカテゴリ一覧へ反映済み。公開用ビルド・Pagesとも成功。
- **通常CI**：テスト555件・lintは成功。生成ジョブだけが**20分の上限で停止**しました。[対象CI](https://github.com/fuhitonakagawa/my-tech-blog-rss-feed/actions/runs/36734436911)
- **外部取得テスト**：318件成功・8件失敗。こちらは別途問題が残っています。


----



もう次は、いまからの更新分しか来ない？
これは初回のみ？


----


**今回の1,099件が、次回また一括通知されることはありません。** dedupへの掲載履歴が残っているためです。

ただし、**今後は「今から公開された記事だけ」になるわけではありません。**

- 新しく公開された記事 → 通知対象
- 過去8日以内で、取得失敗などにより今後初めて取り込めた記事 → 通知対象
- dedupへ掲載済みの記事 → 再取得しても新着扱いにしない

つまり、今回の大量投稿は補完開始時の過去分取り込みですが、**今後も未取得だった過去記事が少し遅れて届く可能性はあります。** また、RSS掲載済みでもSlack側でまだ投稿していない分は、後から届く場合があります。
